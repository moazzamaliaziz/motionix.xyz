When we started prototyping the Motionix video compressor, we planned to ship ffmpeg.wasm. It's the obvious choice — every web video tool has used it since 2019. Less than a month in, we tore it out and replaced it with Mediabunny + straight WebCodecs. Here's why.

## The ffmpeg.wasm assumption

The pitch is simple: bundle ffmpeg as WASM, run it in a worker, get a full video toolchain in 4 KB of code calls. Reality in 2026:

- **Download size.** WASM bundle is ~8.5 MB gzipped. That's a one-time hit, but on a 3G connection it's 30+ seconds.
- **Memory usage.** ffmpeg.wasm loads the entire video into memory. A 200 MB video needs 400+ MB of RAM.
- **Speed.** WASM runs at ~60% of native speed. A 5-minute transcode takes 8+ minutes in the browser.
- **Codec support.** H.264 encoding works, but hardware acceleration is unavailable from WASM.

## The WebCodecs alternative

WebCodecs is a browser API that exposes the same hardware video encoders that native apps use. It's available in Chrome, Edge, and Safari 16.4+.

- **Download size.** Zero. The API is built into the browser.
- **Memory usage.** Streams frames — doesn't load the entire video into RAM.
- **Speed.** Hardware-accelerated. A 60 MB MP4 transcodes in 30-60 seconds on a typical laptop.
- **Codec support.** H.264 with hardware encoding. AV1 support coming.

## The numbers

| Metric | ffmpeg.wasm | WebCodecs |
|--------|-------------|-----------|
| Bundle size | 8.5 MB | 0 MB |
| Memory (200MB video) | 400+ MB | ~50 MB |
| Transcode speed | ~0.5x realtime | ~2x realtime |
| Hardware acceleration | No | Yes |
| Browser support | All | Chrome, Edge, Safari |

## Why we chose WebCodecs

1. **No download cost.** Users don't wait for an 8 MB WASM bundle.
2. **Hardware acceleration.** Modern laptops have dedicated video encoders. Using them is 3-4x faster.
3. **Streaming processing.** We process frames one at a time instead of loading the entire video.
4. **Better user experience.** A 60 MB video compresses in under a minute instead of 5+ minutes.

## The trade-off

WebCodecs isn't available in Firefox yet (~75% browser coverage in 2026). We fall back to a simpler approach for Firefox users.
